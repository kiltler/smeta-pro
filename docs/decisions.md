# Журнал решений

Формат записи: дата — решение — почему.

---

**2026-07-09 — Биллинг: billing_events, ленивое продление, лимит считает сметы.**
Идемпотентность (вебхуков И попыток автосписания) — таблица billing_events
с уникальным ключом события; телу вебхука не доверяем, платёж перечитывается
из API ЮKassa. Продление без крона: при обращении пользователя после
period_end создаётся автосписание по сохранённому способу (попытка
идемпотентна через тот же механизм), grace 3 дня, затем эффективно Free без
удаления данных; отмена = «работает до конца периода», автосписаний нет.
ЮKassa — свой httpx-клиент (~60 строк) вместо SDK; тестовый/боевой режим
различаются только кредами магазина в env. Лимит Free считает СМЕТЫ (создание
и дублирование); договор и акт к своей смете бесплатны — блокировать сделку
на полпути хуже для конверсии, чем «подарить» два PDF. Водяной знак
фиксируется в payload-снапшоте по тарифу на момент создания документа.

**2026-07-09 — Статус документов расширен значением 'paid' (решение владельца).**
Раздел 5 CLAUDE.md фиксировал draft|sent|approved; по явному указанию
владельца (задача 6) добавлен 'paid' — отметка оплаты нужна как триггер
напоминания про чек НПД (штраф за невыдачу — 20% суммы). Миграция меняет
только CHECK-констрейнт; downgrade переводит paid → approved. Договор и акт
создаются парой из согласованной сметы (parent_id → смета), публичной ссылки
не имеют (подписываются на бумаге), payload — общий снапшот: позиции сметы +
данные заказчика + срок работ. НПД-формулировки в договоре (422-ФЗ, материалы
«по поручению и за счёт Заказчика», язык результата без трудовых терминов)
покрыты смок-тестами, чтобы правки шаблона их не потеряли. Сумма прописью —
своя функция ~40 строк вместо зависимости num2words.

**2026-07-09 — Фиче-флаг PARSE_ENABLED (по умолчанию false).**
Живой LLM недоступен (нет кредитов на аккаунте Anthropic) — ИИ-режимы
«Голос»/«Текст» спрятаны за env-флагом PARSE_ENABLED. При false /parse
отвечает 503, фронт показывает только «Шаблоны» (флаг отдаёт публичный
GET /config). Тесты парсера работают на моках; живой смок-тест сам
скипается при отсутствии ключа или кредитов. Включение — одна переменная
в .env, без изменения кода.

**2026-07-09 — Смета: статусы, публичная страница серверным HTML.**
Статусы: draft (создана) → sent (клиент впервые открыл ссылку — бесплатный
«клиент посмотрел») → approved (кнопка «Согласовать», идемпотентно).
Публичная страница /e/{uuid} рендерится сервером (Jinja2) — клиенту не нужна
PWA, страница работает в любом браузере из мессенджера. PDF генерируется
при создании сметы и лежит в хранилище (stateless); срок ссылки = сроку
сметы (14 дней), после — 410. Дубль сметы = новый документ с тем же
payload-снапшотом, новыми номером/ссылкой/сроком/PDF.

**2026-07-09 — ИИ-парсер: claude-sonnet-5, JSON-схема, матчинг по названиям.**
Модель — claude-sonnet-5 (стек фиксирует sonnet; id настраивается через env
ANTHROPIC_MODEL). Формат ответа гарантирован структурированным выводом API
(output_config.format с JSON-схемой) — без парсинга свободного текста.
Модель возвращает названия позиций/комплектов дословно из каталога, а не id:
скопировать название надёжнее, чем числовой id (галлюцинированный id молча
сматчится не с тем). Сервер матчит названия к id и раскрывает комплекты;
несматченное — честно в unrecognized. Системный промпт один на всех
пользователей и кэшируется (cache_control), каталог уходит в user-сообщение.
Thinking отключён: парсеру важна скорость. Сортировка комплектов «по частоте
использования» — счётчики в localStorage браузера, без изменения схемы БД.

**2026-07-05 — Фронтенд: Vue 3 + Vite без UI-библиотек и стора.**
PWA по стеку из CLAUDE.md; сверх vue-router ничего не добавляем: экранов мало,
состояние живёт в компонентах, стили — свой CSS (крупные элементы «под
перчатки»). Роутинг — hash-режим (не требует настройки history-fallback ни
в vite dev, ни в будущем nginx). Manifest + service worker с кэшем оболочки
дают установку на экран и офлайн-заглушку. В dev фронт раздаёт vite-сервер
в контейнере node (сервис frontend в compose) и проксирует /api на backend;
прод-сборка (vite build → nginx) — в задаче 8.

**2026-07-05 — Вход по телефону: таблица auth_codes, PyJWT, лимиты в БД.**
Добавлена таблица `auth_codes` (нет в разделе 5 CLAUDE.md — служебная):
телефон, HMAC-хэш кода (голый sha256 4-значного кода перебирается мгновенно,
поэтому HMAC с SECRET_KEY), TTL, счётчик попыток (максимум 5 — защита от
перебора), отметка использования. Rate limit (3 кода/час на номер) считается
по строкам той же таблицы — без Redis, код stateless (принцип 3).
JWT — библиотека PyJWT (легковесная, только токены, в отличие от python-jose).
Авторизация приватных роутов — FastAPI-зависимость `get_current_user`
(идиоматичная замена middleware, подключается на роутер целиком).

**2026-07-05 — SQLAlchemy в синхронном режиме (psycopg 3), без asyncpg.**
Нагрузка MVP небольшая, FastAPI выполняет sync-эндпоинты в тредпуле без
блокировки. Синхронный код проще в написании и отладке (принцип
«простота > элегантность»), Alembic работает с тем же URL без второго
драйвера. Перейти на async можно точечно позже, если появится узкое место.
