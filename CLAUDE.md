## 1. О проекте

«СметаПро» — SaaS для частных мастеров (первая ниша — кондиционерщики):
смета голосом/текстом/шаблонами за минуты, PDF с брендом мастера,
публичная ссылка для согласования клиентом, договор и акт одной кнопкой.

## 2. Стек

- Backend: Python 3.12, FastAPI, SQLAlchemy 2.x (sync), Alembic
- БД: PostgreSQL 16
- Хранилище файлов: S3-совместимое (локально — MinIO), доступ только через `app/storage.py`
- PDF: WeasyPrint (HTML-шаблоны в `app/templates/pdf/`)
- ИИ-парсер: Anthropic API (промпты в `app/prompts/`)
- Фронт: PWA, мобайл-фёрст
- Локальная разработка: docker compose

## 3. Правила работы

- Задачи выполняются строго по одной. Фичи вне текущей задачи — в `docs/backlog.md`, не в код.
- Архитектурные решения фиксируются в `docs/decisions.md` (дата, решение, почему).
- Эксплуатация (деплой, откат, проверки) — в `docs/runbook.md`.
- После каждой задачи: тесты проходят, проверено руками, закоммичено.
- Секреты — только через переменные окружения (`.env`, не коммитится). В репозитории — `.env.example`.
- Комментарии, документация и тексты интерфейса — на русском.

## 4. Структура репозитория

```
smeta-pro/
├── app/                    # приложение FastAPI
│   ├── main.py             # точка входа, создание приложения
│   ├── config.py           # настройки из переменных окружения
│   ├── db.py               # подключение к БД (engine, session)
│   ├── storage.py          # единственная точка доступа к S3/MinIO
│   ├── models/             # SQLAlchemy-модели
│   ├── routers/            # HTTP-роуты (health, auth, price, parse, ...)
│   ├── services/           # бизнес-логика и интеграции (sms, billing, ...)
│   ├── prompts/            # промпты и датасет для ИИ-парсера
│   └── templates/
│       └── pdf/            # HTML-шаблоны документов (estimate, contract, act)
├── alembic/                # миграции БД
├── docs/
│   ├── backlog.md          # идеи и отложенные фичи
│   ├── decisions.md        # журнал архитектурных решений
│   └── runbook.md          # эксплуатация: деплой, откат, чек-листы
├── scripts/                # служебные скрипты (сиды, дампы, ...)
├── tests/                  # pytest
├── docker-compose.yml      # локальная разработка: api + postgres + minio
├── Dockerfile
├── requirements.txt
├── alembic.ini
├── .env.example            # все переменные окружения с комментариями
└── README.md
```

## 5. Модель данных (основные таблицы)

`users`, `profiles`, `price_items`, `bundles` (items — jsonb:
`{price_item_id, qty_default, ask_qty}`), `documents` (payload — снапшот),
`subscriptions`, `usage_counters`, `parse_logs`.
Детали — в задаче 1.

## 6. Тесты

- pytest; приоритет — биллинг, лимиты, парсер (эталонные диктовки).
- Тест — часть задачи, а не отдельная задача.

## 7. Деплой

- Один сервер, три compose-файла: dev (`docker-compose.yml`),
  `docker-compose.staging.yml`, `docker-compose.prod.yml` — разные порты, env-файлы, БД.
- nginx + certbot; `deploy.sh` (образ → staging), `promote.sh` (тот же образ → prod,
  перед миграцией автодамп БД), `rollback.sh` (откат образа + восстановление дампа).
- Ежедневный `pg_dump` в хранилище, хранение 30 дней.
- CI: тесты на PR, автодеплой `main` → staging. Детали — в задаче 8.
